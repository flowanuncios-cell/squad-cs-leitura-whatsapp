## FASE 1 — ENTRADA | D0–D1

**Objetivo da fase:** o cliente deixa de ser uma venda e passa a ser uma operação aberta.

### 1.1 Kickoff — passagem do comercial para a operação
| | |
|---|---|
| **Responsável** | CS |
| **SLA** | D0 + 4h úteis |
| **Checklist** | ☐ Contrato assinado em mãos · ☐ Resumo comercial recebido (o que foi vendido, promessa feita, verba combinada, prazo prometido) · ☐ Expectativas e "pegadinhas" registradas · ☐ Contatos e decisor identificados |
| **Evidência** | Card do cliente criado no Trello com o resumo comercial anexado |

> ⚠️ O erro mais caro do onboarding acontece aqui: operação assume um cliente sem
> saber **o que o comercial prometeu**. Se o resumo comercial não existir, ele é
> pedido por escrito antes de qualquer outra coisa.

## FASE 2 — PREPARAÇÃO | D1–D4

**Objetivo da fase:** Performance recebe direcionamento estratégico e identidade
prontos para trabalhar — sem depender de mais uma reunião.

### 2.1 Reunião de briefing
| | |
|---|---|
| **Responsável** | GT (apoio: CS) |
| **SLA** | até D3 |
| **Checklist** | ☐ Roteiro de briefing seguido ([`templates/briefing.md`](templates/briefing.md)) · ☐ Reunião gravada · ☐ Dúvidas em aberto listadas no fim da call · ☐ Próximos passos combinados com data |
| **Evidência** | Gravação + briefing preenchido na pasta `01-Briefing` |

### 2.2 Objetivo e meta
| | |
|---|---|
| **Responsável** | GT |
| **SLA** | D4 |
| **Checklist** | ☐ Objetivo de negócio declarado (não "mais visibilidade") · ☐ Meta **numérica** com prazo · ☐ Métrica principal escolhida (CPL, CPA, ROAS…) · ☐ Meta validada com o cliente |
| **Evidência** | Linha "Objetivo e meta" preenchida no briefing, com o número |

> Sem número, não há otimização possível — só opinião.

### 2.3 Oferta / PUV

### 2.4 Público

### 2.5 Concorrência

|---|---|
| **Responsável** | CR (apoio: GT) |

| **Checklist** | ☐ 3 concorrentes mapeados · ☐ Biblioteca de anúncios consultada · ☐ Ângulos que eles usam anotados · ☐ Brecha identificada (o que ninguém está falando) |
| **Evidência** | Doc de concorrência na pasta `02-Marca` |

### 2.6 Canais e funil
| | |
|---|---|
| **Responsável** | GT |
| **SLA** | D4 |
| **Checklist** | ☐ Canais escolhidos com justificativa · ☐ Funil desenhado do anúncio até a venda · ☐ Destino do lead definido (WhatsApp, formulário, LP, CRM) · ☐ Quem atende o lead e em quanto tempo |

## FASE 3 — INTEGRAÇÃO TÉCNICA | D4–D10

**Objetivo da fase:** a infraestrutura existe e está **testada** — não "o cliente
disse que mandou o acesso".

Esta fase é operada pelo [`04-checklist-integracao.md`](04-checklist-integracao.md),
com três estados por item:

```
⬜ Não iniciado  →  🟡 Pendente/Bloqueado  →  ✅ Validado
```

### 3.1 Solicitação formal de acessos
| | |
|---|---|
| **Responsável** | CS |
| **SLA** | D4 |
| **Checklist** | ☐ Lista única enviada ao cliente (não pingada aos poucos) · ☐ Passo a passo de como conceder cada acesso · ☐ Prazo combinado com data · ☐ Responsável do lado do cliente nomeado |
| **Evidência** | Mensagem/e-mail com a lista, no card |

### 3.2 Meta (BM, página, Instagram, conta de anúncios)
| | |
|---|---|
| **Responsável** | TEC |
| **SLA** | D6 |
| **Checklist** | ☐ Acesso de parceiro na BM · ☐ Página do Facebook · ☐ Instagram vinculado · ☐ Conta de anúncios com nível de acesso correto · ☐ Meio de pagamento ativo |
| **Evidência** | Print do acesso ativo na BM |

### 3.3 Google (Ads, Meu Negócio / Perfil da Empresa)
| | |
|---|---|
| **Responsável** | TEC |
| **SLA** | D6 |
| **Checklist** | ☐ Conta Google Ads vinculada ao MCC · ☐ Perfil da Empresa com acesso · ☐ Faturamento configurado · ☐ Histórico da conta verificado (campanhas antigas, penalidades) |
| **Evidência** | Print da vinculação aceita |

### 3.4 Site / LP
| | |
|---|---|
| **Responsável** | TEC |
| **SLA** | D6 |
| **Checklist** | ☐ Acesso ao site/CMS ou ao desenvolvedor do cliente · ☐ Página de destino definida · ☐ Velocidade e versão mobile conferidas · ☐ Formulário/WhatsApp funcionando de verdade (teste manual) |
| **Evidência** | Print do teste de envio do formulário recebido |

### 3.5 Pixels, tags, GTM/GA4
| | |
|---|---|
| **Responsável** | TEC |
| **SLA** | D8 |
| **Checklist** | ☐ Pixel Meta instalado · ☐ Tag do Google instalada · ☐ GTM publicado (quando aplicável) · ☐ GA4 recebendo dados · ☐ Sem duplicidade de disparo |
| **Evidência** | Print do event manager / GA4 recebendo evento de teste |

### 3.6 Eventos e tracking validados
| | |
|---|---|
| **Responsável** | TEC |
| **SLA** | D8 |
| **Checklist** | ☐ Evento de conversão principal definido · ☐ Evento disparando em **teste real** (não só no modo de teste) · ☐ Conversão importada na plataforma de anúncio · ☐ Origem do lead identificável (UTM/parâmetro) |
| **Evidência** | Print do evento recebido + registro no card |

> **Nenhuma campanha sobe sem este item em ✅.** Campanha sem tracking é dinheiro
> gasto sem aprendizado — o prejuízo não é o valor investido, é o mês perdido.

### 3.7 Saldo / meio de pagamento
| | |
|---|---|
| **Responsável** | ADM (apoio: CS) |
| **SLA** | D8 |
| **Checklist** | ☐ Cartão/boleto ativo na conta · ☐ Limite compatível com a verba · ☐ Responsável pelo pagamento identificado · ☐ Data de virada de fatura anotada |
| **Evidência** | Print do meio de pagamento ativo + campo preenchido na planilha |

## FASE 5 — APRENDIZADO | D10–D40

**Objetivo da fase:** transformar os primeiros 30 dias em conhecimento sobre o
negócio do cliente — não em pânico de CPL.

### Rotina obrigatória da fase

| Frequência | O que | Resp. |
|---|---|---|
| Diário | Entrega, saldo, erros, anúncios reprovados | GT |
| 2x/semana | Ciclo de otimização documentado | GT |
| Semanal | Relatório + leitura do funil com o cliente | GT + CS |
| Semanal | Checagem de qualidade de lead com quem atende | CS |
| Quinzenal | Revisão de criativos / novos ângulos | CR |

### 5.1 Acompanhamento de entrega
| | |
|---|---|
| **Responsável** | GT |
| **SLA** | Diário |
| **Checklist** | ☐ Campanha entregando · ☐ Sem anúncio reprovado · ☐ Saldo suficiente para os próximos 7 dias · ☐ Ritmo de gasto compatível com o mês |
| **Evidência** | Registro diário na planilha/board |

### 5.2 Leitura de indicadores
| | |
|---|---|
| **Responsável** | GT |
| **SLA** | 2x/semana |
| **Checklist** | ☐ Indicadores conforme o objetivo (CTR, CPC, CPM, CPL, CPA) · ☐ Comparado com a projeção do 4.3 · ☐ Etapa do sistema onde está o gargalo identificada · ☐ Hipótese escrita antes de mexer |
| **Evidência** | Comentário no card com data, número e hipótese |

### 5.3 Qualidade dos leads
| | |
|---|---|
| **Responsável** | CS (apoio: GT) |
| **SLA** | Semanal |
| **Checklist** | ☐ Amostra de leads revisada com quem atende · ☐ % de lead qualificado estimada · ☐ Motivos de desqualificação anotados · ☐ Tempo de resposta do cliente medido |
| **Evidência** | Bloco de qualidade no relatório semanal |

> Lead ruim quase nunca é só problema de público. Na maioria das vezes é promessa
> desalinhada, formulário fácil demais, ou atendimento lento. Ver
> [`06-manual-treinamento.md`](06-manual-treinamento.md#4-tabela-de-diagnóstico).

| **Evidência** | Log de otimizações no card |

### 5.5 Ordens de Serviço

| **Responsável** | GT (executa: CR/TEC) |

| **Checklist** | ☐ OS no template · ☐ Objetivo da peça descrito · ☐ Prazo acordado · ☐ Entrega conferida antes de subir |

| **Responsável** | CS |

| **Checklist** | ☐ Grupo do cliente respondido dentro do horário de atendimento · ☐ Pedidos virando card (nada "combinado só no WhatsApp") · ☐ Planilha e base atualizadas · ☐ Pasta organizada |

## FASE 6 — OPERAÇÃO CONTÍNUA | D40+

**Objetivo da fase:** manter a operação organizada e previsível, com ciclos
estratégicos em vez de reação.

### Ritmo operacional

| Frequência | Rotina | Resp. | Evidência |
|---|---|---|---|
| **Diário** | Entrega, saldo, erros, grupo do cliente | GT + CS | Registro no board |
| **Semanal** | Relatório semanal (Stract/Make) + leitura de funil | GT | Relatório enviado |
| **Semanal** | Ciclos de otimização + OS | GT | Log no card |
| **Quinzenal** | Revisão de criativos / novos ângulos | CR | Novos criativos no ar |
| **Mensal** | Relatório mensal + reunião de performance | GT + CS | Relatório + ata |
| **Mensal** | Controle de saldo e fechamento de verba | ADM | Planilha fechada |
| **Mensal** | Atualização de bases e documentação | CS | Pasta e planilha atualizadas |
| **Trimestral** | Análise trimestral + **novo ciclo estratégico** | LS + GT | Documento de ciclo |

### 6.1 Automação e dados
| | |
|---|---|
| **Responsável** | TEC |
| **SLA** | Contínuo (revisão mensal) |
| **Checklist** | ☐ Stract conectado e atualizando · ☐ Make rodando sem erro · ☐ Chat/servidor operando · ☐ Falhas de integração tratadas em até 24h |
| **Evidência** | Painel/relatório atualizado na data |

### 6.2 Reunião interna de squad
| | |
|---|---|
| **Responsável** | LS |
| **SLA** | Semanal |
| **Checklist** | ☐ Clientes em risco listados · ☐ Gates travados revisados · ☐ Carga do time conferida · ☐ Decisões registradas com dono e prazo |

### 6.3 Ciclo estratégico trimestral
| | |
|---|---|
| **Responsável** | LS + GT |
| **SLA** | Trimestral |
| **Checklist** | ☐ Resultado do trimestre vs. meta · ☐ O que aprendemos sobre o negócio do cliente · ☐ O que muda no próximo trimestre · ☐ Nova meta numérica acordada com o cliente |
| **Evidência** | Documento de ciclo + reunião com o cliente |

## Resumo em 3 camadas

| Fase | O que o gestor precisa fazer | Evidência de conclusão |
|---|---|---|
| **Entrada** | Organizar cliente | Grupo + Trello + planilha + pasta |
| **Estratégia** | Entender negócio | Briefing + funil + objetivo numérico |
| **Integração** | Preparar infraestrutura | Acessos + tracking validados |
| **Ativação** | Colocar mídia no ar | Campanha ativa + Doc da 1ª Campanha |
| **Aprendizado** | Coletar e interpretar dados | Otimizações documentadas |
| **Performance** | Escalar ou corrigir | Indicadores + OS + decisões registradas |
| **Gestão** | Manter operação organizada | Relatórios + reuniões + bases atualizadas |
